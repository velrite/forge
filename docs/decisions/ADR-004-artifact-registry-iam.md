# ADR-004: Artifact Registry - Single Repo, Scoped CI Identity, Scanning Cost

## Status
Accepted

## Context
Phase 3 needs a container registry with image scanning, and a way for
CI (Phase 6) to push images without a downloadable key file.

## Decision
- One Docker repository (forge-images) for all golden-path services,
  not one repo per service.
- Immutable tags enforced at the repo level.
- Vulnerability scanning enabled project-wide via Container Scanning
  API - scans run automatically on push.
- A dedicated service account (forge-ci-pusher) with
  roles/artifactregistry.writer scoped to ONLY this repository, not
  project-level Artifact Registry access. Wired to GitLab CI via
  Workload Identity Federation in Phase 6 - no key file at any point.

## Alternatives Rejected
- Per-service repos: no real isolation benefit at this scale, adds IAM
  surface to manage for no gain.
- Project-level artifactregistry.writer role: rejected - a leaked
  credential would compromise every repo in the project instead of one.
- Service account key file: rejected per ADR-001's no-key-files stance.

## Cost Impact
Vulnerability scanning costs approximately $0.26 per image scanned
(verified against current GCP community reporting, not GCP's own
pricing page directly - flagged as worth re-verifying against official
pricing before this project handles meaningful image volume). At demo
scale (a handful of pushes), this is a few dollars total, not a
recurring cost. Will be tracked explicitly once FinOps (Phase 12)
exists.

## Consequences
Every service generated by the golden path template (Phase 5) pushes
into this one repo, image-path-namespaced by service name. CI's
identity can never touch anything outside forge-images, even if fully
compromised.

## Revisit Conditions
If image volume grows enough that scanning cost becomes material, or
if a second team/repo needs actual isolation from this one.
